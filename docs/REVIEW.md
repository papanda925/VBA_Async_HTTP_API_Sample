# 疑似ペルソナ100回レビュー記録

## レビューの位置付け

10種類の利用者・専門家を想定し、各ペルソナで観点を変えながら10回ずつ、合計100回の静的レビューを実施しました。

これは、実在する100人の人間によるレビューではありません。疑似ペルソナを用いたセルフレビューです。また、作成環境にWindows版Excel/VBEがないため、実機コンパイルや通信試験の代わりにはなりません。

判定の意味:

- `確認`: 要件を満たしていることを確認
- `修正`: 指摘をソースまたは文書へ反映
- `実機`: 静的確認だけでは確定できず、`TESTING.md`へ実機手順を記載

## 100回レビュー後の主な修正

- クライアント用とサーバー用の導入手順を完全に分離
- `excel.exe /x`による別プロセス起動を追加
- 1冊の`.xlsm`から同じブックの読み取り専用サーバーを自動起動可能に変更
- readyState `DONE`とHTTP成功を区別
- 初回バイト受信時の`ReDim Preserve`を通常の`ReDim`へ修正
- 対象外で不完全なVBA6互換宣言を削除し、VBA7向けへ明確化
- Windows SDKに合わせ、WSADATAをWin64/Win32で別フィールド順に修正
- Traceシート再初期化時のAutoFilter処理を修正
- 新規接続時に前回のTraceIdを消去
- 応答X-Trace-Idと要求IDの一致をクライアントで記録
- 不正なTraceIdを応答ヘッダーへ反映しない検証を追加
- `SO_EXCLUSIVEADDRUSE`でローカル待受ポートを排他的に確保
- Traceシート操作より先に`Debug.Print`へ記録
- Shell系コマンドは起動しない一方、明示操作で別Excelプロセスを起動することをSECURITYへ明記
- サーバー開始エラーを後始末前に退避
- 文字コード、実機差、報告に必要な環境情報を追加
- 正常、遅延、500、404、接続失敗、キャンセル、停止の試験を文書化

## 残る確認事項

次は静的レビューでは確定できません。

1. Windows版Excel 32ビットでのVBAProjectコンパイル
2. Windows版Excel 64ビットでのVBAProjectコンパイル
3. MSXML 6.0のイベント通知順序と接続失敗時の挙動
4. Winsock構造体とAPI宣言の実機動作
5. 日本語本文のUTF-8往復
6. `Application.OnTime`の版別タイミング差
7. ブック終了時の予約取消しとExcelプロセス終了

これらは[TESTING.md](TESTING.md)の手順で確認し、確認できた事実と未確認事項を分けて記録します。
